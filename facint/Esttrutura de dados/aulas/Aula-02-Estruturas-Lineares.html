🎤 **Fala do Professor:** "Sejam bem-vindos à segunda aula de Organização e Manipulação de Estruturas de Dados. Na aula passada, entendemos o que são estruturas de dados e como medir eficiência com Big O. Hoje vamos mergulhar nas estruturas lineares: arrays, listas encadeadas, pilhas e filas. São as estruturas mais utilizadas no dia a dia de um engenheiro de software."

🎤 **Fala do Professor:** "Ao final desta aula, vocês devem ser capazes de explicar o que é uma estrutura linear, manipular arrays e listas, implementar pilhas e filas em JavaScript e, o mais importante, saber qual estrutura usar em cada situação."

🎤 **Fala do Professor:** "Estrutura linear é aquela onde os elementos ficam um atrás do outro, como uma fila. Pensem numa prateleira: o primeiro livro, o segundo, o terceiro — sempre em sequência. Arrays, listas, pilhas e filas são todos exemplos de estruturas lineares."

🎤 **Fala do Professor:** "Vejam a diferença: numa estrutura linear, cada elemento tem no máximo um vizinho antes e um depois. Numa árvore, um elemento pode ter vários filhos. Hoje nosso foco é 100% nas lineares."

🎤 **Fala do Professor:** "O array é a estrutura linear mais fundamental. Ele guarda elementos em posições vizinhas na memória, numeradas a partir do zero. Se sei o índice, vou direto ao elemento — é como saber o número da estante na biblioteca."

🎤 **Fala do Professor:** "Reparem que acessar frutas[3] leva o mesmo tempo que acessar frutas[0]. Não importa a posição: o cálculo do endereço é direto. Por isso o Big O é O(1). E quando o índice não existe, o JavaScript retorna undefined em vez de travar."

🎤 **Fala do Professor:** "Este é o slide mais importante sobre arrays. Gravem: push e pop são O(1), trabalham no final. Mas unshift, shift e splice mexem nas posições dos outros elementos, então são O(n). Em arrays grandes, isso faz diferença real."

🎤 **Fala do Professor:** "Busca linear é o jeito mais simples de procurar: olha um por um até encontrar. Com 5 cidades, é instantâneo. Com 5 milhões de registros, isso vira um problema. Por isso precisamos conhecer outras estruturas ao longo da disciplina."

🎤 **Fala do Professor:** "Esta tabela é a síntese do array. Guardem a regra: final é rápido, início e meio são lentos. Quando o sistema precisa ficar inserindo e removendo no início, o array não é a melhor escolha — e é aí que entram as listas encadeadas."

🎤 **Fala do Professor:** "Vejam o problema: no array, para inserir na posição 2, preciso empurrar o 30 e o 40 uma casa para a direita. Se o array tiver um milhão de elementos, preciso deslocar quase um milhão de itens. Na lista encadeada, basta ajustar dois ponteiros e pronto. É por isso que as listas existem."

🎤 **Fala do Professor:** "A lista encadeada funciona como uma caça ao tesouro: cada nó te diz onde está o próximo. Não existe índice — para chegar ao terceiro elemento, preciso passar pelo primeiro e pelo segundo. A vantagem? Inserir e remover são operações rápidas se eu já estiver na posição certa."

🎤 **Fala do Professor:** "A diferença central é a memória. O array ocupa posições seguidas — por isso o acesso é direto. A lista pode ter nós espalhados pela memória, mas cada um sabe onde está o próximo. Array é prateleira: vou direto na estante 3. Lista é corrente: preciso seguir elo por elo."

🎤 **Fala do Professor:** "Cada nó é um objeto que guarda duas coisas: o valor e o endereço do próximo nó. Quando conectamos os nós, formamos a cadeia. O último nó aponta para null porque não existe próximo. A variável 'head' é a entrada da lista — sem ela, não sabemos onde a lista começa."

🎤 **Fala do Professor:** "Vamos construir a lista passo a passo. Primeiro, criamos três nós isolados — cada um com valor e proximo null. Depois, conectamos: Ana aponta para Bruno, Bruno aponta para Carlos. Carlos continua apontando para null porque é o último. Por fim, a variável head aponta para Ana, que é a porta de entrada da lista."

🎤 **Fala do Professor:** "A grande mágica da lista encadeada: para inserir, basta ajustar os ponteiros. Não preciso deslocar nada. No array, inserir no meio empurra todos os elementos. Na lista, eu apenas religo os nós. Mas atenção: primeiro preciso encontrar a posição, e isso é O(n)."

🎤 **Fala do Professor:** "Remover é o inverso de inserir: faço o nó anterior pular o nó que quero remover. Não há deslocamento, mas preciso encontrar o nó anterior, o que exige percurso. Reparem como o nó B simplesmente deixa de ser apontado — ele fica 'solto' na memória e o coletor de lixo do JavaScript cuida do resto."

🎤 **Fala do Professor:** "Percorrer uma lista é como seguir um fio: começo no primeiro, vou seguindo as referências até chegar ao null. Não tem como pular etapas. Se a lista tem 100 elementos, preciso dar 100 passos. Compare com o array: lá eu vou direto ao índice 99 em O(1)."

🎤 **Fala do Professor:** "A pergunta-chave é: o que meu sistema faz mais vezes? Se é busca por índice, use array. Se são inserções e remoções no meio, use lista. Playlists, histórico de undo/redo, implementação de filas e pilhas eficientes — tudo isso usa listas encadeadas nos bastidores."

🎤 **Fala do Professor:** "Pilha é uma estrutura onde tudo acontece no topo. Pensem numa pilha de pratos: não dá pra tirar o prato de baixo sem remover os de cima. O último prato que colocamos é o primeiro que tiramos. Por isso LIFO — Last In, First Out."

🎤 **Fala do Professor:** "Push coloca no topo, pop tira do topo. E o peek, que aparece na tabela, é só uma consulta: olho o topo sem tirar nada. No JavaScript não existe peek nativo, então usamos pilha[pilha.length - 1]. Olhem como a pilha muda: cada operação só afeta o topo."

🎤 **Fala do Professor:** "Este é um exemplo clássico de pilha no mundo real. Quando vocês apertam Ctrl+Z no VS Code ou no Word, o programa desfaz a última ação primeiro. É literalmente uma pilha: cada ação é empilhada, e ao desfazer, desempilhamos a mais recente."

🎤 **Fala do Professor:** "A fila é o oposto da pilha. Pensem na fila do banco: quem chega primeiro é atendido primeiro. FIFO — First In, First Out. Entra pelo final, sai pelo início. Ninguém pula a fila."

🎤 **Fala do Professor:** "Enqueue é push — insere no final. Dequeue é shift — remove do início. Reparem que shift é O(n) porque desloca os elementos. Para filas eficientes de verdade, usamos listas ou estruturas dedicadas. Mas para entender o conceito, esse modelo com array funciona bem."

🎤 **Fala do Professor:** "Imprimantes usam fila: o primeiro documento enviado é o primeiro a sair. Se mandarmos 3 arquivos, eles serão impressos na ordem de envio. Isso é FIFO. O mesmo vale para filas de atendimento em sistemas, processamento de pedidos e muito mais."

🎤 **Fala do Professor:** "Lado a lado, fica claro: a pilha é como empilhar pratos — só mexo no de cima. A fila é como uma fila de banco — o primeiro que chega é o primeiro que sai. São comportamentos opostos e cada um serve para situações diferentes."

🎤 **Fala do Professor:** "Esta tabela é a síntese da aula. Não existe estrutura perfeita — cada uma tem pontos fortes e fracos. O array é ótimo para acesso por índice, mas lento para inserir no início. A lista é o inverso. Pilha e fila são restrições sobre listas: uma só mexe no topo, a outra só mexe nas pontas."

🎤 **Fala do Professor:** "Vocês já usam essas estruturas todos os dias sem perceber. Quando apertam Ctrl+Z, é uma pilha. Quando o sistema processa pedidos na ordem de chegada, é uma fila. Quando guardam itens num carrinho, é um array ou lista. Identificar qual estrutura se encaixa em cada cenário é a habilidade central desta disciplina."

🎤 **Fala do Professor:** "Encerramos com a mesma frase da aula anterior: não existe a melhor estrutura, existe a mais adequada. Se preciso de acesso rápido por índice, array. Se preciso de inserções e remoções frequentes, lista. Se preciso de LIFO, pilha. Se preciso de FIFO, fila. A decisão é de engenharia."

🎤 **Fala do Professor:** "Rode mentalmente cada linha. Na pilha: push A, B, C. Pop tira C → x = C. Push D. Pop tira D → y = D. Sobrou A e B. Na fila: push 1, 2, 3. Shift tira 1 → a = 1. Push 4. Shift tira 2 → b = 2. Sobrou 3 e 4."

🎤 **Fala do Professor:** "Agora são perguntas abertas. Para o desfazer, é pilha — LIFO. Para o banco, é fila — FIFO. Para inserir no início, use unshift, mas o custo é O(n). E a lista encadeada é melhor quando há muitas inserções e remoções, porque não precisa deslocar elementos."
