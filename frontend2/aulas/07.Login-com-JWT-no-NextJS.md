## ❓ O grande dilema: onde guardar o JWT?

<div style="display:flex;gap:12px;margin-top:10px;">

<div style="flex:1;border:2px solid #C22820;border-radius:10px;padding:12px;">
<b style="color:#C22820;">❌ localStorage / sessionStorage</b>
<ul style="font-size:0.8em;">
<li>Acessível por qualquer JS da página</li>
<li>Vulnerável a <b>XSS</b> (roubo do token)</li>
<li>Não é enviado automaticamente</li>
</ul>
</div>

<div style="flex:1;border:2px solid #116329;border-radius:10px;padding:12px;">
<b style="color:#116329;">✅ Cookie httpOnly + Secure</b>
<ul style="font-size:0.8em;">
<li>JavaScript <b>não</b> consegue ler o token</li>
<li>Enviado automaticamente nas requisições</li>
<li>Protegido contra XSS + HTTPS</li>
</ul>
</div>

---

<div style="flex:1;border:2px solid #999;border-radius:10px;padding:12px;">
<b>⚠️ Cookie sem httpOnly</b>
<ul style="font-size:0.8em;">
<li>Melhor que localStorage</li>
<li>Mas ainda legível via JS</li>
<li>Usar só para dados não sensíveis</li>
</ul>
</div>

</div>

<div style="background:#5C2034;color:#fff;border-radius:10px;padding:14px;margin-top:18px;text-align:center;">

**Decisão da aula:** o JWT será gravado em **cookie `httpOnly`** pelo Next.js — inacessível ao JavaScript do navegador.

</div>

## ⚡ 3. Server Action de login — `actions/auth.ts`

```ts
'use server';

import { cookies } from 'next/headers';
import { redirect } from 'next/navigation';

const API = process.env.API_URL ?? 'http://localhost:3001';

export async function login(_prev: unknown, formData: FormData) {
  const email = formData.get('email');
  const senha = formData.get('senha');

  const res = await fetch(`${API}/auth/login`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ email, senha }),
  });

  if (!res.ok) {
    return { error: 'E-mail ou senha inválidos' };
  }

  const { token } = await res.json();

  const cookieStore = await cookies();          // ← await no Next 15/16
  cookieStore.set('token', token, {
    httpOnly: true,                             // ← JS não lê o token
    secure: process.env.NODE_ENV === 'production',
    sameSite: 'lax',
    path: '/',
    maxAge: 60 * 15,                            // ← 15 minutos (exp curto)
  });

  redirect('/dashboard');
}
```

## 🔍 6. Quem valida o token? Só a API Express!

<div style="background:#C22820;color:#fff;border-radius:10px;padding:14px;">

🔑 **Regra de ouro:** o segredo (`JWT_SECRET`) **nunca sai do backend**. O Next.js **não verifica a assinatura** — ele só checa se o cookie **existe** e **repassa o token** para a API, que é a única autoridade.

</div>

```ts
// middleware.ts (Next 15) / proxy.ts (Next 16)
import { NextRequest, NextResponse } from 'next/server';

export function middleware(req: NextRequest) {
  const token = req.cookies.get('token')?.value;

  // ✅ Só verificamos a PRESENÇA do token (gate de entrada)
  if (!token) {
    return NextResponse.redirect(new URL('/login', req.url));
  }

  // 🔐 Assinatura e expiração? Só a API Express valida (aula 06)
  return NextResponse.next();
}
```
---

<div style="background:#fbeaea;border-left:6px solid #C22820;padding:12px;border-radius:8px;margin-top:12px;">

⚠️ **Nunca copie o `JWT_SECRET` para o Next.js!** Se o token for inválido ou estiver expirado, quem descobre é a **API (resposta `401`)** — e o Next.js trata o erro limpando o cookie e voltando ao `/login`.

</div>

## 📡 7. Requisições autenticadas

### Opção A — Server Component lendo o cookie (recomendada)

```tsx
import { cookies } from 'next/headers';

export default async function DashboardPage() {
  const cookieStore = await cookies();
  const token = cookieStore.get('token')?.value;

  const res = await fetch(`${process.env.API_URL}/perfil`, {
    headers: { Authorization: `Bearer ${token}` },
    cache: 'no-store',
  });

  const perfil = await res.json();

  return <h1>Olá, {perfil.nome}!</h1>;
}
```
---
### Opção B — Route Handler como proxy interno

O navegador chama `/api/perfil` do Next.js, que repassa o `Authorization` para a API — a URL do backend nunca fica exposta no cliente.

## 🔒 11. Segurança — casando com a aula `06.JWT`

<div style="display:flex;gap:12px;">

<div style="flex:1;background:#eaf3ea;border-top:6px solid #116329;border-radius:10px;padding:14px;">

**✅ Faça**

* Cookie **`httpOnly` + `secure` + `sameSite`**
* Access token com **`exp` curto** (minutos)
* Deixar a **validação da assinatura** só na API — a chave não sai do backend
* Use **HTTPS** sempre em produção
* Mensagens de erro **genéricas** no login

</div>

<div style="flex:1;background:#fbeaea;border-top:6px solid #C22820;border-radius:10px;padding:14px;">

**❌ Evite**

* Guardar JWT em **`localStorage`**
* Levar o **`JWT_SECRET` para o frontend** — ele vive **só no backend**
* Confiar no **`alg` do header** recebido
* Colocar **dados sensíveis no payload** (é só codificado, não criptografado!)
* Tokens de **longa duração**
* Expor detalhes internos na resposta de erro

</div>

</div>


## 🏁 Resumo e Conclusão

* 🔐 **Cookie `httpOnly`** é o lugar seguro para o JWT no Next.js
* ⚡ **Server Actions** são o lugar certo para **gravar cookies** e chamar a API
* 🔑 **Quem valida o JWT é só a API Express** — a chave secreta **nunca sai do backend**
* 🛡️ **Middleware (15) / Proxy (16)** protegem as rotas (só checam se o cookie **existe**)
* 📡 Requisições autenticadas usam o header **`Authorization: Bearer <token>`
* 🚪 **Logout** = apagar o cookie no servidor
* ⏱️ **Token expirado (`401`)?** Limpa o cookie e volta ao `/login`
* 🎨 A identidade visual **Unipar** (`#C22820` e `#5C2034`) pode ser aplicada via CSS variables

> **A aula `06.JWT` (Backend) + esta aula (Frontend) = sistema de autenticação completo!**
